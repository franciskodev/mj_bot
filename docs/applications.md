# Заявки в INTERPOLOV

Набор ведётся только в INTERPOLOV. В новой заявке выбирается один игровой сервер.

Команда `/applications reset_cooldown user:@пользователь` сбрасывает кулдаун подачи заявки для выбранного пользователя. Доступна с уровня 5; снизить требование через `/access command` нельзя. Сброс сохраняется после перезапуска бота, история заявок остаётся прежней. Новая заявка запускает обычный кулдаун. Блокировка подачи заявок и запрет на вторую открытую заявку сохраняются. Действие записывается в журнал заявок.

После обновления и перезапуска бота администратор с уровнем 5 настраивает роли отдельно для каждого игрового сервера:

```text
/applications roles server:Seattle recruiter_role:@Recruiter Seattle high_role:@High Seattle
/applications roles server:Orlando recruiter_role:@Recruiter Orlando high_role:@High Orlando
/applications roles server:Denver recruiter_role:@Recruiter Denver high_role:@High Denver
/applications roles_show
```

Имена ролей в примерах условные: выберите существующие отдельные роли сотрудников соответствующего сервера. Если таких ролей нет, создайте их в Discord и назначьте нужным сотрудникам. Общая роль рекрутёров или High не подходит для разделения доступа. Одна роль не может быть настроена для заявок двух серверов. Роль самого игрового сервера и семейная роль также не подходят: их получают обычные участники.

Настроенные роли дают уровень 2 рекрутёрам и уровень 4 High через общую систему доступа. Другие привязки `/access` сохраняются, но общий уровень доступа сам по себе не открывает тикеты и не разрешает обработку чужих заявок.

Тикет видят кандидат, бот, рекрутёры и High выбранного сервера. Администраторы Discord видят все тикеты. Проверка кнопок дополнительно учитывает сервер заявки и канал; исключение разработчика уровня 6 сохраняется. Если сотруднику назначены отдельные роли нескольких серверов, он получает доступ к заявкам этих серверов.

При старте и изменении настройки бот пересчитывает права существующих тикетов, убирает прежние разрешения и обновляет карточки заявок. Старые заявки с несколькими серверами остаются доступны кандидату и администраторам. До настройки обеих ролей сервера новые заявки на него не создаются, а старые тикеты доступны кандидату и администраторам. Неудачные обновления отражаются в журнале; команда настройки также сообщает об ошибках. После исправления прав повторите команду.

Общий журнал заявок с копиями анкет и транскриптами доступен только администраторам и боту. Если бот не может ограничить доступ к журналу, он не отправляет туда новые конфиденциальные данные. История внутри карточки показывает только заявки на тот же игровой сервер.

Боту нужны права на изменение разрешений каналов, создание и просмотр тикетов, отправку сообщений и файлов, чтение истории и выдачу ролей при принятии. Существующая панель обновляется при старте; для новой панели используйте `/applications setup`.

Исторические файлы транскриптов сохраняются. Служебный путь установки и имя systemd-сервиса не меняются, чтобы существующий запуск продолжал работать.

## HTML-транскрипты

После рассмотрения бот отправляет в закрытый журнал HTML-файл с перепиской и
карточку: заявитель, игровой сервер, результат, кто рассмотрел заявку, количество
сообщений и вложений. Скачайте файл и откройте в браузере. В нём видны авторы,
аватары, время в UTC, изменения сообщений, ответы с переходом внутри файла,
карточки бота, реакции и вложения. Для поиска используйте Ctrl+F.

Небольшие вложения встраиваются в HTML и доступны без Discord. Размер одного
встраиваемого файла ограничен 2 МиБ; общий бюджет учитывает лимит загрузки сервера.
Крупные и недоступные для скачивания файлы остаются ссылками с соответствующей
пометкой. Ссылки Discord могут истечь. Внешние изображения и скрипты автоматически
не загружаются; HTML из сообщений отображается как текст.

На диске сохраняются `application-ID-transcript.html` и резервный
`application-ID-transcript.json`. Исходный файл анкеты `application-ID.json`
не перезаписывается транскриптом. JSON не прикладывается к карточке транскрипта.

Перед удалением тикета бот повторно сохраняет переписку, включая сообщения после
решения, и обновляет HTML в существующей карточке журнала. Удаление разрешается
только после успешного сохранения и отправки файла в закрытый архив. При ошибке
тикет остаётся на месте. Повторное действие или перезапуск повторяет архивирование.

После обновления завершённые тикеты, которые ещё существуют в Discord и имеют
старый JSON-транскрипт, получают HTML при запуске бота. Старые файлы уже удалённых
тикетов сохраняются без изменений. Переписка, удалённая до создания архива,
не восстанавливается.
